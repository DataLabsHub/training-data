# Add indicator enrichment for multiple indicator types

Provide a new `indicator-enrichment` command that accepts indicators either through the `indicator_list` argument or by extracting them from free-form `text`. It should identify supported IP, URL, Domain, CVE, and File indicators, remove duplicate values, group them by type, and invoke the corresponding enrichment behavior so users receive one consolidated result. The command should accept optional `external_enrichment`, `brands`, `additional_fields`, `raw_context`, and `ignore_indicator_limit` arguments; the first three are passed through to the underlying enrichment operations, `raw_context` controls whether underlying raw contexts are included, and more than 100 unique valid indicators should be rejected by default unless the limit is explicitly ignored. Invalid or unsupported values should be represented in the response rather than silently discarded, while an input with no actionable indicators should produce a clear user-facing status or validation error. Return readable Markdown and a unified `IndicatorEnrichment` context containing the successful results and any reported invalid or unsupported items, with raw child-enrichment keys omitted by default and retained when `raw_context` is true. The command must expose clear success and failure status information and handle partial child-command failures without losing successful enrichment data.

The implementation must be in `Packs/AggregatedScripts/Scripts/IndicatorEnrichment/IndicatorEnrichment.py`, importable as the `IndicatorEnrichment` module. The module must expose `IndicatorType`, `EnrichmentRequest`, `EnrichmentResult`, `ResponseFormatter`, `EnrichmentService`, `UnsupportedIndicator`, `AllExecutionsFailedError`, `EnrichmentRequestBuilder`, `ValidationError`, `GracefulExit`, and `main`. Its public API is:
1. Define `IndicatorType` with members `IP`, `URL`, `DOMAIN`, `CVE`, and `FILE`, plus classmethod `resolve_from_string(value)`. It returns `IP` for `ip` and `IPv4`, `URL` for `url`, `DOMAIN` for `Domain`, `FILE` for `file`, and `CVE` for `cve`, case-insensitively; it returns `None` for `garbage_type`, `email`, whitespace-only input, `None`, and other unsupported values.
2. Define `UnsupportedIndicator(type, value)` with accessible `type` and `value` fields, and define the exception classes `ValidationError`, `AllExecutionsFailedError`, and `GracefulExit`.
3. Define `EnrichmentRequest(valid_indicators_by_type, unsupported_items, unknown_items, duplicates_removed_count, sub_command_arguments, include_raw_context)` with those accessible attributes and a `total_valid_count` property equal to the total number of values in `valid_indicators_by_type`.
4. Define `EnrichmentResult()` with public `enriched_data`, `raw_context`, `markdown_sections`, and `execution_errors` accumulators, initialized respectively as an empty list, empty mapping, empty list, and empty list.
5. Define `EnrichmentRequestBuilder(raw_arguments)` and no-argument `build_and_validate()`. It accepts `indicator_list` as a comma-separated value or list and uses `argToList` and `auto_detect_indicator_type` to classify list items. It extracts `text` by calling `execute_command("extractIndicators", {"text": text})` and reads extracted values from `EntryContext.ExtractedIndicators`; extracted keys and auto-detected names are resolved through `IndicatorType.resolve_from_string`.
6. The builder preserves first-seen order, deduplicates the same indicator value across `text` and `indicator_list`, and increments `duplicates_removed_count` once per removed occurrence. Supported values are grouped under their `IndicatorType`; a detected but unsupported type is recorded as `UnsupportedIndicator(type, value)`, and an untyped or unknown value is recorded in `unknown_items`.
7. The builder's `EnrichmentRequest.sub_command_arguments` contains the provided `external_enrichment`, `brands`, and `additional_fields` values and no unrelated arguments; `include_raw_context` reflects `raw_context` and defaults to `False` when omitted. `total_valid_count` counts unique supported values only.
8. The builder raises `ValidationError` containing `No valid indicators provided` when no input is supplied or an `indicator_list` supplies no valid values. Text-only input whose extraction finds no actionable indicators raises `GracefulExit` containing `No valid indicators provided`. More than 100 unique valid indicators raises `ValidationError` containing `Indicator limit exceeded` and `limit is 100`, unless `ignore_indicator_limit` is true; with that flag true, all valid indicators are retained.
9. Define `EnrichmentService(request)` and no-argument `execute()`. An empty `valid_indicators_by_type` returns an `EnrichmentResult` with no data or errors and does not call `BatchExecutor.execute_batch`. For grouped values, child work is executed through `BatchExecutor`; each `(entry, human_readable, error)` result is parsed so matching child context entries become dictionaries in `enriched_data` with their indicator-type `Type`, human-readable output is retained in `markdown_sections`, and errors are retained in `execution_errors` without discarding successful data.
10. Define `ResponseFormatter()` with `format(result, request)`, returning a `CommandResults`-compatible object with `readable_output` and `outputs`. Successful Markdown sections are preserved exactly. When duplicates exist, prepend `Note: Removed {count} duplicate indicator occurrences before enrichment.`; invalid rows use heading `### Invalid or unsupported indicators` and columns `Type`, `Value`, `Status`, `Message`, with unknown values represented as `Unknown`, `Error`, and `Not a valid indicator.`. The unified successful and invalid entries are emitted under `IndicatorEnrichment`, in success-then-error order.
11. By default, `ResponseFormatter` removes child enrichment keys such as `IPEnrichment` from `outputs` while preserving other context keys such as `Core`, `EndpointData`, and unified `IndicatorEnrichment`. When `include_raw_context` is true, child enrichment keys are retained. If `enriched_data` is empty and `execution_errors` is nonempty, `format` raises `AllExecutionsFailedError` with `Fatal error while executing enrichment. View the logs or try again.` followed by each error on its own line.
12. Define no-argument `main()`. It obtains arguments from `demisto.args()`, builds and validates an `EnrichmentRequest`, calls `EnrichmentService.execute()` with no arguments, formats the result, and passes it to `return_results`. A `GracefulExit` is returned through `return_results` as a `CommandResults`-compatible object with the exception text as `readable_output` and empty `outputs`; `ValidationError` and `AllExecutionsFailedError` are passed to `return_error` using their messages. Unexpected exceptions are logged with `demisto.error` and passed to `return_error` with a message containing `Failed to execute !indicator-enrichment` and the original exception text.
