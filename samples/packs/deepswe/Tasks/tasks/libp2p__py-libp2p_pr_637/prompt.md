# Add NetStream Lifecycle State

Add stream state support to py-libp2p network streams. The original issue asks "To add a Stream State mechanism in py-libp2p to track the lifecycle of a Stream. This would allow both internal components and external consumers to determine whether a stream is open, closed, reset, or has errored." It also explains the motivation: "Currently, py-libp2p has no explicit notion of a stream's state. As a result: Errors from operations on a closed or reset stream are only caught at runtime; There's no unified API to check whether a stream is in a valid operational state; Bugs like double-close, write-after-close, or inconsistent state transitions are harder to catch; This makes reasoning about stream lifecycle harder for transport and application layers."

Expose a structured `StreamState` lifecycle for `NetStream` with the public states `INIT`, `OPEN`, `CLOSE_READ`, `CLOSE_WRITE`, `CLOSE_BOTH`, `RESET`, and `ERROR`. Newly created streams should begin in `INIT`, streams should move to `OPEN` when established, read-side and write-side closes should be tracked independently before reaching `CLOSE_BOTH`, resets should put the stream in `RESET`, and unexpected I/O failures should put the stream in `ERROR`. The `state` property must remain awaitable and return the current `StreamState`, and `set_state(state)` must allow tests and callers to update the state deliberately.

Operations should validate the current state before touching the underlying muxed stream: reads from `ERROR`, `RESET`, or read-closed states must fail with stream-specific errors; writes from `ERROR`, `RESET`, or write-closed states must fail similarly; close operations should update the corresponding half-close state; and reset must still be allowed from `ERROR` so callers can clean up. Unexpected exceptions raised by the underlying muxed stream during read or write should be converted into `StreamError` and leave the stream in `ERROR`, while expected stream lifecycle exceptions should preserve their existing behavior.

Provide an awaitable `is_operational()` method that reports whether the stream can still perform useful I/O. It should be true for active or half-closed lifecycle states such as `INIT`, `OPEN`, `CLOSE_READ`, and `CLOSE_WRITE`, and false for terminal states such as `CLOSE_BOTH`, `RESET`, and `ERROR`. State reads, state writes, and state-dependent I/O checks must be synchronized so concurrent readers, writers, and state updates cannot observe inconsistent transitions.

## Public API
1. `NetStream` and `StreamState` must be available from `libp2p.network.stream.net_stream`. `StreamError`, `StreamClosed`, `StreamEOF`, and `StreamReset` must be available from `libp2p.network.stream.exceptions`. The existing `IMuxedStream` interface is available from `libp2p.abc` and is the type of the wrapped stream.
2. `NetStream.__init__(muxed_stream, swarm_conn)` accepts the wrapped `IMuxedStream` followed by a `swarm_conn` value, which may be `None`; both positional calls and the keyword `swarm_conn=` are supported.
3. `state` is an awaitable property with return type `StreamState`. `set_state(state: StreamState) -> None` is awaitable and updates the current state. `read(n: int | None = None) -> bytes`, `write(data: bytes) -> None`, `close() -> None`, `close_read() -> None`, `close_write() -> None`, `reset() -> None`, and `is_operational() -> bool` are awaitable methods with the shown parameter names, order, and default.
4. A newly constructed `NetStream` has state `StreamState.INIT`; an established stream is moved to `StreamState.OPEN`. `StreamState` exposes exactly the public members `INIT`, `OPEN`, `CLOSE_READ`, `CLOSE_WRITE`, `CLOSE_BOTH`, `RESET`, and `ERROR`.
5. An operation attempted while the state is `ERROR` raises `StreamError` before using the underlying stream. In particular, `read()`, `write(data)`, `close_read()`, and `close_write()` raise `StreamError` with message substrings `Cannot read from stream; stream is in error state`, `Cannot write to stream; stream is in error state`, `Cannot close read on stream; stream is in error state`, and `Cannot close write on stream; stream is in error state`, respectively. `reset()` remains allowed from `ERROR` and leaves the state `RESET`.
6. If the underlying stream raises an unexpected exception during `read()` or `write()`, the wrapper raises `StreamError` with a message containing `Read operation failed` or `Write operation failed`, respectively, and changes to `ERROR`; expected EOF, reset, and existing stream-lifecycle exceptions retain their existing exception behavior.
7. `is_operational()` returns `True` for `INIT`, `OPEN`, `CLOSE_READ`, and `CLOSE_WRITE`, and `False` for `CLOSE_BOTH`, `RESET`, and `ERROR`. State transitions and state-dependent I/O checks are atomic and remain safe if an operation is cancelled while concurrent public state or I/O operations are in progress.
